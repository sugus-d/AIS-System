# 标注即时图像 — 上线前人工验收清单

> 适用功能：用户标注完成回到受检者报告页时，即时显示标注连线图；重新分析使用新标注文件。
> 改动范围：`POST /api/render`（算法服务）、`completed` 即时渲染（Express）、标注图 `&av=` 缓存失效（Express）、前端先刷新图再等重分析（React）。

---

## 0. 前置检查（先确认环境就绪）

- [ ] 三个进程指向**同一个** `AIS_RESULTS_ROOT`：Express 服务、标注平台、算法服务（现网预测流程已依赖，此处只做确认）。
- [ ] 算法服务已用新代码重启，`POST /api/render` 已生效（可看启动日志，或 `curl -X POST http://127.0.0.1:8000/api/render` 应返回 422「仅支持 .ply 文件」而非 404）。
- [ ] Express 服务已用新代码重启（`server/routes/annotation.ts`、`reports.ts`、`services/algorithm.ts` 改动已编译生效）。
- [ ] 前端已用新代码重建（`client/pages/AnalysisReport.tsx` 改动已生效）。
- [ ] 准备 1 个已分析、已有报告、可进入标注的测试病例（含 PLY）。

---

## 1. 回归：现有功能不受影响

- [ ] **首次分析**：新建病例 → 上传 PLY → 分析 → 报告四张图（标注图/莫尔/热力图/法向角）正常生成。
- [ ] **普通重分析**：报告页点「重新分析」→ Cobb 角 / 热力图 / moire 刷新正常。
- [ ] **标注平台加载**：进入标注 → 初始 mesh 与预标 landmark 正常加载（确认没被新增渲染目录污染）。

---

## 2. 核心验收：标注完成后即时显示标注图

- [ ] 打开报告 → 进入标注 → 修改若干 landmark → 完成标注（跳回报告页）。
- [ ] 回到报告页后，**标注连线图秒级更新**（不必等整条重分析跑完）。
- [ ] 标注图上的 landmark 位置与标注平台里改的一致。
- [ ] 打开浏览器 F12 → Network：确认 `landmarks.png` 被重新请求（URL 带 `&av=<时间戳>`）。

---

## 3. 核心验收：重分析使用新标注文件

- [ ] 等待重分析任务完成（进度从分析中变为完成）。
- [ ] Cobb 角 / 指数随新 landmark 变化（改动足以影响预测时应有差异）。
- [ ] 热力图 / moire 刷新，标注图指向新目录（`?v=<新任务目录>`）。

---

## 4. 边界与降级

- [ ] **只改 landmark（不动 ROI）**：标注图即时更新；热力图 / moire 保持不变，等重分析刷新。
- [ ] **改了 ROI（去衣笔刷）**：标注图即时反映新体形；热力图 / moire 仍为旧 ROI，等重分析统一刷新（Phase 1 预期行为）。
- [ ] **算法服务不可用**：完成标注不报错、不卡死，页面正常返回，等重分析（降级为与改前一致的行为）。
- [ ] **从未标注过的报告**：标注图仍走原 `landmarks.png`，无 404 / 破图。

---

## 5. 缓存失效验证

- [ ] 连续两次进入标注并修改：第二次完成后标注图**仍即时更新**（`&av=` 每次都会变，不命中旧缓存）。

---

## 6. 收尾检查

- [ ] 浏览器 F12 Console 无报错。
- [ ] 服务端日志无未捕获异常（`render failed, falling back to reanalysis` 之外的报错需排查）。
- [ ] 确认标注完成后没有生成新的 `prediction-outputs/<caseId>-*` 目录（不应污染标注平台扫描）。

---

## 通过标准

- 第 1 节全部通过（无回归）。
- 第 2、3 节全部通过（核心功能）。
- 第 4、5 节全部通过或符合「预期行为」说明。
- 第 6 节无异常。
